Credential setup

Wire auth
Send API calls to https://api.hubapi.com with Authorization: Bearer <OAuth access token or static access token> and JSON. OAuth token exchange/refresh uses application/x-www-form-urlencoded POST bodies. Developer API keys are only for documented developer-key endpoints and are passed as hapikey (often with appId). A Super Admin or a user with Developer tools access can create a scoped account service key in Development > Keys > Service keys. Send it as a Bearer credential for REST calls.
Oauth flow
OAuth 2.0 authorization-code: redirect the user to HubSpot consent, receive a single-use code on the registered redirect URI, exchange it for tokens, store token metadata securely, send the access token as Bearer, and refresh before expiry. The only documented app-level client_credentials flow is for the webhooks journal API.
Oauth endpoints
Authorization: https://app.hubspot.com/oauth/authorize. Current versioned token endpoint: POST https://api.hubspot.com/oauth/2026-09/token for grant_type=authorization_code or refresh_token; the same endpoint supports client_credentials for webhook-journal app tokens. Token introspection: POST https://api.hubspot.com/oauth/2026-09/token/introspect.
Scope and refresh
Scopes are space-separated in the authorization request and configured as required, optional or conditionally required. The current exchange returns scopes, hub_id and expires_in=1800; access tokens last 30 minutes. Refresh uses grant_type=refresh_token with client_id, client_secret and refresh_token. Optional scopes can be omitted when the portal/user lacks access and then are absent from resulting tokens; connector scope changes require MCP reinstallation.
Test setup

Live setup

For broad distribution use marketplace OAuth; sign the AUP, use the sample install URL, and submit a listing for manual review. Pre-listing marketplace OAuth is limited to 25 non-test installs; after listing it is unlimited. Private OAuth defaults to 10 customer portals. This is distinct from Plaid’s own OAuth service for customers/partners/services. The latter supports client_credentials, refresh_token and RFC 8693 token-exchange grants.
Oauth endpoints
Plaid documents POST /oauth/token, /oauth/introspect and /oauth/revoke on the Plaid API. Dashboard MCP examples call https://production.plaid.com/oauth/token; the remote MCP endpoint itself is https://api.dashboard.plaid.com/mcp/.
Scope and refresh
OAuth scopes documented by Plaid are user:read, user:write, exchange and mcp:dashboard. OAuth access tokens are short-lived (the published example has expires_in 900); use refresh_token with grant_type=refresh_token to refresh. This is separate from Item access_token, which does not expire by default but can be rotated with /item/access_token/invalidate or revoked by /item/remove.
