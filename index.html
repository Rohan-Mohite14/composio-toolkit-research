02 HubSpot CRM and Sales APIs (Developer Platform 2026-09)CRM and marketing automation OAuth 2.0, TokenFree developer, sandbox or quota pathFree or limited free usage REST · BroadMCP · Vendor
Build within documented free scope

Create or obtain a standard HubSpot account with a free developer test account, create a current Developer Platform app, choose private/static for a single-account prototype or private/marketplace OAuth for distribution, configure the minimum CRM scopes, and run the documented contacts read/search fixture. For MCP, create the connector and test get_user_details in MCP Inspector before implementing writes. Obtain Super Admin/Marketplace access and the relevant paid subscription only when the chosen object/feature requires it or when submitting/listing publicly.

Search CRM contacts by email. Main constraint is connected account, app scopes and endpoint entitlements. Sales and marketing CRM. Search contacts with private apps or OAuth. Endpoint features depend on plan.

Credential setup
Create a current Developer Platform app/project and choose auth/distribution in app-hsmeta.json. For OAuth, configure at least one HTTPS redirect URL (localhost HTTP is permitted for testing), required/optional scopes, client ID and client secret, and host an OAuth callback/token backend. For a static app, install it in the target account and copy the generated access token. Legacy private apps cannot be newly created after 2026-10-26, so do not use that legacy creation path for a new build. A Super Admin or a user with Developer tools access can create a scoped account service key in Development > Keys > Service keys. Send it as a Bearer credential for REST calls.
Wire auth
Send API calls to https://api.hubapi.com with Authorization: Bearer <OAuth access token or static access token> and JSON. OAuth token exchange/refresh uses application/x-www-form-urlencoded POST bodies. Developer API keys are only for documented developer-key endpoints and are passed as hapikey (often with appId). A Super Admin or a user with Developer tools access can create a scoped account service key in Development > Keys > Service keys. Send it as a Bearer credential for REST calls.
Oauth flow
OAuth 2.0 authorization-code: redirect the user to HubSpot consent, receive a single-use code on the registered redirect URI, exchange it for tokens, store token metadata securely, send the access token as Bearer, and refresh before expiry. The only documented app-level client_credentials flow is for the webhooks journal API.
Oauth endpoints
Authorization: https://app.hubspot.com/oauth/authorize. Current versioned token endpoint: POST https://api.hubspot.com/oauth/2026-09/token for grant_type=authorization_code or refresh_token; the same endpoint supports client_credentials for webhook-journal app tokens. Token introspection: POST https://api.hubspot.com/oauth/2026-09/token/introspect.
Scope and refresh
Scopes are space-separated in the authorization request and configured as required, optional or conditionally required. The current exchange returns scopes, hub_id and expires_in=1800; access tokens last 30 minutes. Refresh uses grant_type=refresh_token with client_id, client_secret and refresh_token. Optional scopes can be omitted when the portal/user lacks access and then are absent from resulting tokens; connector scope changes require MCP reinstallation.
Test setup
Create a free developer test account from a standard account (up to 10; 90-day inactivity expiry) and use it as the isolated test portal. For CLI development install Node.js 20+ and @hubspot/cli, then run hs account auth; for remote MCP create a connector, register the redirect URL, and test with MCP Inspector using Streamable HTTP, OAuth and PKCE.
Live setup
For one live standard account use a private/static app and its generated token. For multiple selected live accounts use private OAuth with an allowlist (10 accounts by default). For broad distribution use marketplace OAuth; sign the AUP, use the sample install URL, and submit a listing for manual review. Pre-listing marketplace OAuth is limited to 25 non-test installs; after listing it is unlimited. Private OAuth defaults to 10 customer portals. An app created in an eligible Solutions Partner portal can reach 100. Private static auth is limited to one standard portal. Marketplace review removes the 25-install cap.
Distribution requirements
Current app-hsmeta.json distribution is marketplace or private. Marketplace requires OAuth; private can use OAuth for allowlisted accounts or static auth for one account. OAuth redirect URLs must be HTTPS except http://localhost for testing. Marketplace listing requires a public setup guide, proper single-app OAuth identity, only needed scopes, terms agreement and manual Ecosystem Quality review; Super Admin is required to submit.
Base url and version
API root is https://api.hubapi.com. The current API reference is date-version 2026-09, with paths such as /crm/objects/2026-09/contacts and /crm/objects/2026-09/{object}/search. HubSpot says new integrations should use the latest date version; legacy endpoints remain documented separately.
Resource families
CRM object records and schemas/properties; associations; search; batch and import/export; engagements (calls, emails, meetings, notes, tasks); owners/users/account; pipelines; conversations; marketing/content/campaigns; files/CMS; webhooks and webhooks journal; OAuth/authentication. The MCP adds CRM, activity, content, conversation, marketing email, social and account-context tools, subject to permissions and subscription.
Api reference or spec
Reference: https://developers.hubspot.com/docs/api-reference/latest/overview and the linked versioned guides. HubSpot also publishes per-product OpenAPI 3.0 JSON specs in https://github.com/HubSpot/HubSpot-public-api-spec-collection, but its README says the collection is for internal Postman synchronization, proprietary and not licensed for external use; it is not a single consolidated 2026-09 external bundle.
Mcp endpoint or install
Remote data MCP: Streamable HTTP at https://mcp.hubspot.com; create an MCP connector in HubSpot, copy client ID/secret and configure a PKCE-capable MCP client. Local Developer MCP: install @hubspot/cli (CLI >=8.2.0) and run hs mcp setup, selecting Claude Code, Codex CLI, Cursor, Gemini CLI, VS Code or Windsurf.
Mcp coverage
Remote read tools cover CRM records (contacts, companies, deals, tickets, leads, users, custom objects, lists and beta revenue objects), activities, content/marketing, analytics, communications/conversations, email/social and account context. Write tools cover CRM records/activities, content, campaigns, drafts, pipelines, properties, associations, custom objects, segments and social; sensitive-data/conversation restrictions and user permissions apply. Developer MCP covers local HubSpot Developer Platform/CLI app and CMS tasks. Composio's catalog match is a third-party HubSpot toolkit with 355 tools/2 triggers.
Blocker
New builds cannot use the legacy private-app creation flow (sunset 2026-10-26). A public marketplace build is gated by account/developer setup, correct scopes, AUP, HTTPS callback/backend and manual Ecosystem Quality review; before listing, installs are capped at 25. Remote MCP is gated by a current Developer Platform MCP connector, user-granted permissions and PKCE. Feature-specific gates include subscription tiers and scopes.

Vendor
HubSpot, Inc.
Edition
HubSpot CRM and Sales / standard HubSpot account using the current Developer Platform API reference (2026-09); legacy private/public app creation is sunset but existing legacy apps remain supported.
Region and deployment
Cloud SaaS. HubSpot documents the single API root https://api.hubapi.com and remote MCP endpoint https://mcp.hubspot.com rather than regional API base URLs. OAuth token metadata includes a hublet field (for example na1) and hub_domain, but the checked public docs do not specify a selectable region/deployment base URL; region routing is therefore unresolved beyond HubSpot-managed hublets.
Credential identity
client_id/client_secret identify the Developer Platform app; authorization code is a one-use handoff; access token authenticates calls for the installing user/account; refresh token renews access. OAuth introspection returns app_id, client_id, user_id, user email, hub_id and hub_domain. Static auth token is the single-account app credential; developer API key identifies the developer/app for special endpoints; CLI Personal Access Key authenticates local CLI commands. A Super Admin or a user with Developer tools access can create a scoped account service key in Development > Keys > Service keys. Send it as a Bearer credential for REST calls.
Tenant or org id
The tenant is the HubSpot account/portal identified by hub_id (Hub ID); OAuth metadata also returns hub_domain, user_id and app_id. The installing user's permissions and granted scopes determine accessible data.
Minimum plans by route
No single paid minimum is stated on the core contacts/companies/deals/tickets object guides; standard accounts may be free or paid, with access controlled by product subscription, permissions and scopes. Developer test accounts are free with a 90-day trial of many enterprise features. Documented feature gates include Revenue Hub Professional/Enterprise for beta quote MCP tools and Marketing Hub Professional/Enterprise for AEO; free tools cannot create custom pipelines. Confirm the target object/endpoint's scope and account entitlement before production.
Operation inventory
Count unknown. The current 2026-09 API reference exposes families through versioned guides (CRM objects/search, properties, associations, engagements, account, conversations, marketing/content, automation, webhooks and more); the CRM search guide explicitly lists 19 object search families plus engagements. The official OpenAPI 3.0 repository contains per-product/rollout JSON files and is updated by HubSpot, but its README says it is internal/proprietary and not a consolidated external 2026-09 specification. No total operation count is asserted.
Official sdks and clis
Official SDKs: Node.js, Python, PHP, Ruby and .NET (HubSpot-maintained); Go is explicitly community. Official CLI is @hubspot/cli, installed with npm and used via hs commands including hs api, hs account auth, hs project and hs mcp setup.
Composio toolkit
Composio catalog match: HubSpot toolkit, latest catalog version 20261116_01, OAuth2 and API Key auth, 355 tools and 2 triggers. It documents managed OAuth and custom HubSpot OAuth config, including a Composio callback URL and scope matching; this is a third-party toolkit rather than HubSpot MCP.
Mcp auth status restrictions
Remote MCP uses OAuth with mandatory PKCE; connector permissions are derived from available tools and user-granted permissions, and all actions respect HubSpot user permissions. Reinstall after scope changes. Sensitive Data blocks conversation access through MCP; social writes require social.publish; beta/revenue and AEO features require documented scopes/subscriptions. Local Developer MCP uses the CLI's local authentication. MCP Inspector is a community-maintained test client, not a HubSpot data server.
Private and public routes
Private/static: current Developer Platform app with distribution=private and auth=static, one standard account at a time plus up to 10 developer test accounts. Private OAuth: distribution=private/auth=oauth, hosted backend and 10 accounts by default. Public/marketplace: distribution=marketplace/auth=oauth, hosted backend, AUP and listing review; up to 25 non-test installs before listing and unlimited after listing. Do not treat legacy private/public app creation as a current route because both creation flows are sunset in 2026, although existing legacy apps remain supported. Private OAuth defaults to 10 customer portals. An app created in an eligible Solutions Partner portal can reach 100. Private static auth is limited to one standard portal. Marketplace review removes the 25-install cap.

List deal entries. Main constraint is provisioned DealCloud tenant and user-group permissions. Deal CRM. API key obtains an OAuth client-credentials token. Tenant permissions and separate MCP entitlement apply.

Credential setup
Have a DealCloud administrator assign the intended user to a group with the API capability in Admin > User Management. The user then opens Profile, enables API Key, and copies the API key. Collect the customer site URL and the client ID/secret terminology used by that site; the current Python SDK config uses siteUrl, clientId, and clientSecret. Keep the secret out of source control.
Wire auth
POST {baseUrl}/api/rest/v1/oauth/token with Content-Type: application/x-www-form-urlencoded and grant_type=client_credentials, client_id, client_secret/API key, and space-separated scope. Use the response access_token as Authorization: Bearer {token} on subsequent REST calls.
Oauth flow
Service-to-service OAuth 2.0 Client Credentials; it is not a user authorization-code flow for the REST API. The token page says the access token expires after 900 seconds (15 minutes); obtain a new token by repeating the client-credentials request.
Oauth endpoints
REST token endpoint: {baseUrl}/api/rest/v1/oauth/token. No separate REST authorization endpoint is documented for client credentials. MCP uses standard .well-known OAuth discovery, but the public MCP docs do not spell out the tenant-specific authorization and token URLs.
Scope and refresh
Documented REST scopes are user_management (management), data (data and schema), publish (publications), ri_import (Relationship Intelligence), and backup (backups). Request only needed scopes. The public token docs document 15-minute expiry and repeat-grant renewal, not a refresh-token lifecycle; specialized/deprecated scopes include provider_sync, api, data_provider, and exchange.
Test setup
Use an existing customer site host and API-enabled user. Test token and REST calls in the site Swagger at https://{host}/swagger or import https://{host}/swagger/current into Postman. Start with schema discovery, then a read-only rows call. No public sandbox, seed tenant, or anonymous test credentials are documented.
Live setup
Use the same site-specific host for live data, with an API-enabled user whose group permissions cover the target endpoints and records. For MCP, configure Tools > MCP Servers, use the default or a published custom server, and connect through OAuth; writes require Enable Write Tools and appropriate user permissions.
Distribution requirements
Private/customer distribution requires the customer site, issued credentials, API capability, and least-privilege group/data permissions. Vendor MCP hosted clients are documented; local Claude Code/Codex CLI/Cursor desktop use localhost redirects that must be enabled by the Account Manager. Custom or third-party MCP clients require contacting the Account Manager. No anonymous public API distribution route is documented.
Base url and version
Use the customer site as base host: https://{host}. Core data and schema are versioned /api/rest/v4; OAuth and much administration/Relationship Intelligence routes are /api/rest/v1. Swagger is /swagger and its machine-readable current spec is /swagger/current on the customer host. Publications are now site-specific, replacing the older environment/region endpoint structure.
Resource families
Publisher docs cover authentication, user management, schema, data (cells, rows, history, files/reports), backups, publications/event streaming, and Relationship Intelligence. The current Python SDK additionally documents files, history, template reports, merge, and publications helpers.
Api reference or spec
Official API reference: https://api.docs.dealcloud.com/docs. The docs say each customer host exposes Swagger at https://{host}/swagger and OpenAPI at https://{host}/swagger/current. The exact machine-readable document and operation count are unresolved without a customer site host/spec; the public documentation itself is a generic reference.
Mcp endpoint or install
No package install is required for the hosted server. An admin copies the endpoint from Tools > MCP Servers; the default format is https://[tenant].my.intapp.com/mcp/celeste/DealCloud. Paste that URL into a compatible client and authorize through OAuth. Custom servers require a published Schema Contract and MCP Server.
Mcp coverage
Official tools cover name lookup, record search/details, current user and tenant profile, GraphQL schema introspection/query composition/execution, truncated-result pagination via read_more, entry-form rules, choice/reference/user value lookup, validation without saving, and submit_entry. The default server exposes the full site schema; a custom server scopes objects/fields through a Schema Contract. Writes are disabled until explicitly enabled.
